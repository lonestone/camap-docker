# Rights matrix: which feature needs which right

Reference for the Haxe→TS migration (see `task/refacto-hx-ts/specs/02-groups/rights.md`, GRP-RIG-001…013).

- **Source of truth for behaviour**: the Haxe code in `camap-hx/src` (what production does today).
- **TS column / section B**: what `camap-ts/packages/api-core/src` already enforces.
- ⚠️ marks a check that looks dangerous (missing, too weak, wrong subject, or high-impact by design). Details are in section C, keyed `H-n` (Haxe) and `T-n` (TS).
- Generated by reading the code, not by running it. Every ⚠️ is a *suspected* hole to confirm with a test before treating it as a bug.

## A. The rights

| Right | Stored as | Meaning | Notes |
|---|---|---|---|
| **Superadmin** | `User.rights` flag `Admin` | Passes **every** check in every group | Not a group member. `hasRight` returns true for it (`UserGroup.hx:152`). TS also treats it as a member of every group (UND-031). |
| **GroupAdmin** | `UserGroup.rights` JSON | Manage the group: settings, rights, places, media, group documents | Does **not** imply any other right (GRP-RIG-002). |
| **ContractAdmin (all)** | `ContractAdmin`, `params=null` | Manage every catalog + the whole distribution section | TS: any ContractAdmin entry counts as "all" (CODE-028). |
| **ContractAdmin (n)** | `ContractAdmin`, `params=[id]` | Manage catalog n only | |
| **ContractAdmin (auto)** | derived from claimed vendor | Manage the catalogs of a vendor I claimed | Read-only in the rights editor. |
| **Membership** | `Membership` | Members, memberships, waiting list, member payments | |
| **Messages** | `Messages` | Send messages to members | |
| *Member* | row in `UserGroup` | Belongs to the group, no right | |
| *Logged-in* | session | Any account, member or not | |
| *Anonymous* | none | | |

Helper → right mapping (Haxe `db/User.hx`):

| Helper | Real condition |
|---|---|
| `isAmapManager()` / `isGroupManager()` | Superadmin **or** GroupAdmin of the **session's current group** |
| `canManageContract(c)` | Superadmin **or** ContractAdmin(all or c.id) in **c's own group** ✅ group-aware |
| `isContractManager(c)` | ContractAdmin(all or c.id) in the **session's current group** (⚠️ not c's group) |
| `isContractManager()` (no arg) | Holds **any** ContractAdmin entry, even for one catalog (⚠️ weak) |
| `canManageAllContracts()` | ContractAdmin(all) in the current group |
| `canAccessMembership()` / `canAccessMessages()` | Membership / Messages in the current group |

## C. Why they look dangerous

### Haxe

| Id | Where | Problem | Impact |
|---|---|---|---|
| H-1 | `Place.hx` `doInsert`, `doEdit`, `doView` | No right check at all; only `@logged` on the dispatcher. `doDelete` does require GroupAdmin. Place is looked up by id, with no group check. | Any logged-in user can edit the address of any group's distribution place. |
| H-2 | `Distribution.hx` `doVolunteers`, `doVolunteerRoles`, `doInviteFarmers`, `doListByProductUser` | No check. Objects are loaded by id, no group check. | Any logged-in user can assign volunteers, enable roles, invite vendors, and read the per-member order sheet (names + quantities) of any distribution. |
| H-3 | `ContractAdmin.hx` `doRoles`, `doInsertRole`, `doEditRole`, `doDeleteRole`, `doParticipate`, `doSelectDistrib`, `doBatchOrder`, `doTmpBaskets` | Only the constructor check (`isContractManager()` = any ContractAdmin entry). | A coordinator of catalog A can edit roles, join distributions, and read temp baskets of catalog B (and any group, since the constructor uses the current group). |
| H-4 | `isContractManager(c)` used in `ContractAdmin.doEdit/doAbsences`, `Product.doInsert`, `Distribution.doEdit/doShift/doDelete/doNotAttend/doInsert` | Evaluated against the session's **current** group, not `c.group`. A ContractAdmin(all) in group A passes for a catalog of group B. `canManageContract` does it right. | Cross-group catalog and distribution edits. |
| H-6 | `Product.doExport` | No check. | Any logged-in user can export any catalog's product list (names, prices, refs). Low sensitivity. |
| H-7 | `Transaction.doInsertPayment`, `SubscriptionAdmin.doInsertPayment` | `isContractManager()` with no argument: any ContractAdmin entry, even for one unrelated catalog. No subscription/catalog check. Editing/deleting the same payment needs Membership instead (inconsistent). | A coordinator of one small catalog can credit any member's account. Money. |
| H-8 | `Member.doLoginas` | Target is not checked to belong to the admin's group, only to be in ≤1 group. | A GroupAdmin can impersonate any user who is a member of exactly one *other* group. Impersonation is high-impact by design. |
| H-9 | `AmapAdmin.doEditRight` | Rights are written **before** the self-lockout check and before the non-member check (CODE-029, UND-030). A group admin can grant any right, including to someone he picks from the form data. | Self-lockout leaves a group with no admin; failed validation still writes. |
| H-10 | `ContractAdmin.doDelete` | ContractAdmin(all) can delete a catalog (guarded by a token + no linked orders). | Destructive; confirm "all" rather than GroupAdmin is intended. |
| H-11 | `api/User.doGetFromGroup` | Membership **or any** ContractAdmin entry. Returns member infos (name, email, phone, address). | A one-catalog coordinator reads the whole member directory. |
| H-12 | `/admin/*`, `/db`, `Subscriptions.doReattribute` | Superadmin-only but very powerful: raw SQL admin on `/db`, delete users/groups, add self to any group. | By design; make sure the TS port does not expose an equivalent without audit logging. |
| H-13 | `Install.doDefault` | Creates `admin@camap.tld` / password `admin` if the install flag is absent. | Dangerous if an instance is ever reset or mis-deployed. |

H-5 is intentionally unused (it was a false alarm on commented-out code, removed).

### TS

| Id | Where | Problem | Impact |
|---|---|---|---|
| T-1 | `auth.resolver.ts:138` (`loginAs`), `orders.resolver.ts:80` | `!this.userGroupsService.isGroupAdmin(...)` / `!…canManageAllCatalogs(...)` without `await`: a Promise is always truthy, so the condition is always false and the check never fires. In `loginAs` the check is also run on the **target** `user`, not `currentUser`. | Any logged-in user can impersonate any non-superadmin user in ≤1 group (give a `groupId`). Any logged-in user can read orders of a multi-distribution without a catalog. **Most urgent item here.** |
| T-2 | `userLists.resolver.ts` (4 queries) | No right check, only login; takes a `groupId` with no membership test. | Any logged-in user can list the members of any group by id. |
| T-3 | `waitingLists.resolver.ts` `getWaitingListsOfGroup` | No right check. | Any logged-in user can read any group's waiting list. |
| T-4 | `catalogs.resolver.ts:173` | `canManageCatalog(currentUser, parent.id)` not awaited (and given an id, so it loads the catalog again) → always true. | Members-only and subscribers-only catalog documents are returned to everyone, including anonymous callers if the guard allows them. |
| T-5 | `user-groups.service.ts:112-114` | Any ContractAdmin entry counts as "manage all catalogs" (CODE-028). | A one-catalog coordinator gets group-wide catalog powers (previews, distributions, attendance). |
| T-6 | `user-groups.service.ts:138-140` | Superadmin is treated as a member of every group. | Appears in member counts and lists; see UND-031. |

## D. Suggested next steps

1. Confirm T-1, T-2, T-3, T-4, H-1, H-2, H-3, H-7, H-8 with a characterisation test each (`tests/specs/02-groups/rights.*.spec.ts` is the natural home).
2. Decide, per UND-031, the exact meaning of "all catalogs" and fix `isContractManager()` / `canManageAllCatalogs` to match.
3. In the TS port, enforce one rule per object: the right is evaluated against the **object's** group, never the session's current group.
4. Not covered here: the React/Neo front-end modules (they only hide buttons, enforcement is server-side), `Cron`, `Scripts`, `Api` dispatch, and `canAccessAttention`.
