# Orders, subscriptions (CSA contracts), baskets, order UI

## 1. Scope

Subscriptions (CSA contracts), user orders (`UserOrder`), baskets, default/recurrent orders, minimum-order constraints, stock checks at order time, subscription-related admin pages (forms, balance transfer, payments pages), member history pages, the member ordering UI (`csaCatalog`) and admin batch ordering (`batchOrder`), the legacy Haxe-React `OrderBox`. Absences are in `distributions-volunteers.md`; payments/operations in `payments-operations-reports.md`.


Ownership summary: the whole write path (subscriptions, orders, baskets) lives in Haxe. TS has no mutation for subscriptions/orders/baskets; it has entities, read-only GraphQL fields and the React front (`csaCatalog`, `batchOrder`) that calls the Haxe REST API (`/api/subscription/*`, `/api/catalog/*`) via `camap-ts/packages/front-core/src/modules/csaCatalog/requests.tsx:1-162` (base URL = `CAMAP_HOST + "/api"`, `camap-ts/packages/front-core/src/lib/REST/useRestGetApi.tsx:4-5`).

## 2. Concepts & glossary terms

- **Subscription**: (user, optional user2, catalog, startDate, endDate, `defaultOrders` JSON, `absentDistribIds` CSV) (`camap-hx/src/db/Subscription.hx:9-18`). Every order line must belong to a subscription: `OrderService.make` throws "Impossible d'enregistrer une commande sans souscription." (`camap-hx/src/service/OrderService.hx:109`).
- **Catalog types**: `TYPE_CONSTORDERS = 0` (same order every distribution) and `TYPE_VARORDER = 1` (variable) (`camap-hx/src/db/Catalog.hx:53-54`).
- **UserOrder**: one order line (product, quantity, `productPrice` snapshot, `feesRate`, `paid`, user2, flags).
- **Basket**: one row per (user, MultiDistrib), groups UserOrders of all catalogs; `num` = sequence number inside the MD (`camap-hx/src/db/Basket.hx:15-27,48-66`). Statuses HX: OPEN, CONFIRMED, VALIDATED (`:7-12`); TS adds `PAYMENT_PROCESSING` (`camap-ts/packages/api-core/src/shop/entities/basket.entity.ts:13-19`).
- **Default order**: list of `{productId, quantity, userId2?, invertSharedOrder?}` stored in `Subscription.defaultOrders`; the recurrent order for CONST and the pre-filled order for VAR with `distribMinOrdersTotal > 0`.
- **adminMode**: flag in `SubscriptionService` relaxing checks.
- **SubscriptionTotal operation**: `-getTotalPrice()` operation per subscription (`camap-hx/src/service/SubscriptionService.hx:1059-1091`).
- **Shared (alternating) basket**: CONST only, `user2` + `InvertSharedOrder` flag.
- **Smart quantity**: products with `variablePrice || bulk`, displayed amount = `quantity * product.qt` with unit.
- **Renewal**: no such feature in either codebase; a new season = new catalog + new subscriptions (`ContractAdmin.doDuplicate` copies the catalog, optionally products/distributions, not subscriptions: `camap-hx/src/controller/ContractAdmin.hx:782-900`).
- **OrderBox**: legacy Haxe-React dialog (`camap-hx/js/react/order/**`) used by `contractadmin/orders.mtt` and `ordersByDate.mtt` (`_Camap.initOrderBox(...)`, `camap-hx/lang/master/tpl/contractadmin/orders.mtt:29,107`, `ordersByDate.mtt:66`), talking to `/api/order/*`.

## 4. Business rules

### Vocabulary / data
1. Subscription date bounds: on create/update `startDate` normalised to 00:00:00 and `endDate` to 23:59:59 (`camap-hx/src/service/SubscriptionService.hx:666-667,787-788`). Both must lie inside the catalog dates: start `>= catalogStart && < catalogEnd`, end `> catalogStart && <= catalogEnd` (`camap-hx/src/service/SubscriptionService.hx:405-415`). Start strictly before end (`camap-hx/src/service/SubscriptionService.hx:373-375`).
2. A subscription's distributions = distributions of the catalog with `date >= startDate && end <= endDate`, minus absence distributions when the catalog has absence management (`camap-hx/src/service/SubscriptionService.hx:192-225`). "open" adds `orderStartDate <= now < orderEndDate` (`:202-208`); "past" adds `end <= end of today` (`:209-214`; `getSubscriptionDistribsNb("past")` uses `$date <= endOfToday` `:256`, `getSubscriptionRemainingDistribsNb` uses `$date >= now` `:232`).
3. `Catalog.hasAbsencesManagement()` and `hasDefaultOrdersManagement()` are true for CONST catalogs and VAR catalogs with `distribMinOrdersTotal > 0`; absences additionally need `absentDistribsMaxNb > 0` and both absence dates (`camap-hx/src/db/Catalog.hx:145-160`). `hasConstraints()` = VAR with `distribMinOrdersTotal > 0 || catalogMinOrdersTotal > 0` (`:141-143`).

### Constant vs variable orders
4. CONST: the default order is the recurrent order; `createRecurrentOrders` materialises one `UserOrder` per product per distribution of the subscription (`camap-hx/src/service/SubscriptionService.hx:899-965`). Distributions with `quantities > 1` get the order created `quantities` times (`:947-949`); `make` accumulates same user/product/distribution into one row (`camap-hx/src/service/OrderService.hx:90-97`), multiWeight products stay separate rows (`camap-hx/src/service/OrderService.hx:52-65,90`).
5. VAR: orders are per distribution. Default order exists only if `distribMinOrdersTotal > 0`; stored in `Subscription.defaultOrders` (`camap-hx/src/service/SubscriptionService.hx:1010`); `createRecurrentOrders` creates it on every subscription distribution whose `orderEndDate` is not past (`:922-925`). Existing non-closed orders of the subscription are deleted first (`:906-916`), so re-saving the default order overwrites manual per-distribution edits on all not-yet-closed distributions.
6. For a CONST subscription all orders (including past) are deleted and recreated at the current `product.price` (`camap-hx/src/service/SubscriptionService.hx:909` exempts only VAR; `camap-hx/src/service/OrderService.hx:77`). Non-admin cannot do it once there are past orders: `updateDefaultOrders` throws `PastOrders` when `hasPastDistribOrders && !adminMode` (`camap-hx/src/service/SubscriptionService.hx:989-993`). The admin edit form always re-saves orders when the catalog has default-order management (`camap-hx/src/controller/SubscriptionAdmin.hx:223-272`, `camap-hx/src/service/SubscriptionService.hx:802-804`).
7. VAR without minimums: no default order; the TS wizard skips the "required orders" step (`camap-ts/packages/front-core/src/modules/csaCatalog/CsaCatalogRouter.tsx:101-108`).
8. VAR + `distribMinOrdersTotal > 0`: the hourly cron applies the default order to subscriptions with no order at all on a distribution whose `orderEndDate` fell in the last hour, unless the distribution is an absence (`camap-hx/src/controller/Cron.hx:227-278`, catalog restriction `:229-245`); uses `OrderService.make`, an in-app notification `DEFAULT_ORDER(catalogId)`, then refreshes the total operation; a `make` error is not caught per subscription (effect unverified). See `crons-scheduled-jobs.md`.
9. Shared (alternating) baskets: CONST only. `createSubscription` takes `user2` from the order lines (`checkUser2`: one distinct `userId2` allowed, `camap-hx/src/service/SubscriptionService.hx:759-772,669-673`); `updateSubscription` only overwrites `user2` when non-null (`:790-796`). `UserOrder.getWhosTurn` = parity of the count of catalog distributions from `catalog.startDate` to the distribution date, flipped by `InvertSharedOrder` (`camap-hx/src/db/UserOrder.hx:63-74`). The TS front never sends `userId2` (`camap-ts/packages/front-core/src/modules/csaCatalog/requests.tsx:57-69`, `interfaces.ts:119-122`); alternating baskets can only be set from the HX admin form (`camap-hx/src/controller/SubscriptionAdmin.hx:109-137`). `Distribution.getUserOrders` includes `user2` orders for CONST only (`camap-hx/src/db/Distribution.hx:94-100`).

### Subscription lifecycle
`createSubscription` (`camap-hx/src/service/SubscriptionService.hx:644-703`):
10. Start defaults to the next not-closed distribution date (`getComingOpenDistrib`, `camap-hx/src/service/SubscriptionService.hx:152-159,630-638`; VAR needs `orderStartDate <= now < orderEndDate`, CONST only `orderEndDate > now`); end defaults to catalog end (`:647-653`). The TS REST client never sends dates; only the HX admin form lets dates be chosen (`camap-hx/src/controller/SubscriptionAdmin.hx:73-100,159`).
11. If the user is not a member of the catalog's group: auto-joined when `group.regOption == Open`, otherwise error (`camap-hx/src/service/SubscriptionService.hx:654-661`).
12. Absences (explicit ids or `absenceNb`) applied before validation (`camap-hx/src/service/SubscriptionService.hx:675-682`) with `adminMode=false` hard-coded in the call.
13. `checkSubscriptionBeforeUpdate` (`camap-hx/src/service/SubscriptionService.hx:360-479`): (a) catalog must `hasOpenOrders()` unless `adminMode` (`:363`; `hasOpenOrders` = `UsersCanOrder` flag + inside catalog dates + for VAR at least one distribution currently in its order window, `camap-hx/src/db/Catalog.hx:116-125`); (b) at least one non-old distribution (`:367-370`); (c) date checks (rule 1); (d) non-admin: start >= next open distribution date (`:377-400`); (e) no overlap with another subscription of the same user and same catalog (`:417-466`, `OverlappingSubscription`; per catalog, not per vendor); (f) existing VAR sub: range may not exclude past orders (`hasPastDistribOrdersOutsideSubscription`, `:468-473`, `PastOrders`); (g) non-admin CONST: no past distribution without an order in the range (`:475-478,874-888`, `PastDistributionsWithoutOrders`).
14. After `insert`: default orders (if `hasDefaultOrdersManagement`, `camap-hx/src/service/SubscriptionService.hx:687-690`), then `initialOrders` on top (`:691-694`), `SubscriptionTotal` operation, `areVarOrdersValid` (`:696-697`), "subscription created" notification mails queued (`:699-701,705-757`: `camap-hx/lang/master/tpl/mail/notifications/subscription-created-user.mtt` at `camap-hx/src/service/SubscriptionService.hx:713`, `subscription-created-coordinator.mtt` at `camap-hx/src/service/SubscriptionService.hx:739`, flags `camap-hx/src/service/SubscriptionService.hx:721-722,748-749`), user balance updated (`:701`). The user mail links `https://::HOST:://subscriptions/contract/<catalogId>` (double slash, `subscription-created-user.mtt:2-3`) and `/vendor/view/<id>`.
15. REST create always runs with `adminMode = true` (`camap-hx/src/controller/api/Subscription.hx:50`), bypassing checks (a), (d), (g) of rule 13; compensating guards: explicit `hasOpenOrders` for non-managers (`:45-47`) and the computed start date. `adminMode` is read only at `camap-hx/src/service/SubscriptionService.hx:363,378,475,983,990`, none inside `updateOrders`/`setOrders` (`:1014-1021`). `isGroupManager()` = GroupAdmin right in the session group (`camap-hx/src/db/User.hx:120-134`), while `canManageContract` looks at the catalog's group (`:215-222`).
16. `updateSubscription` (`camap-hx/src/service/SubscriptionService.hx:778-805`): only reachable from the HX admin edit form (`SubscriptionAdmin.hx:294`); requires both dates; locks, applies rule 13, updates, re-creates orders if `hasDefaultOrdersManagement && ordersData != null`. The admin form refuses an absence date outside the new period (`SubscriptionAdmin.hx:283-292`).
17. `deleteSubscription` (`camap-hx/src/service/SubscriptionService.hx:814-838`): refused when orders with `quantity > 0` exist on past distributions (`hasPastDistribOrders`, `:817-819,843-855`) or when any `Payment` operation exists (`:822-824`; balance transfers are `Payment` operations, `:1112,1123`); otherwise deletes all orders (`OrderService.delete(order, true)`), all operations, updates balance, deletes the subscription. Members delete only their own (`camap-hx/src/controller/Subscriptions.hx:36`); admins via token route (`SubscriptionAdmin.hx:47-61`).
18. `getCurrentOrComingSubscription` returns the single subscription of the user for the catalog with `endDate >= (next open distribution date or now)` (`camap-hx/src/service/SubscriptionService.hx:176-180`).
19. Balance transfer: moves `balance` between two subscriptions of the same user by creating two `Payment` operations of type `transfer` (`{type:'transfer'}`, amount `-balance` source, `+balance` target; negative balances allowed) (`camap-hx/src/service/SubscriptionService.hx:1099-1139`, `:1104`). Targets offered = other not-closed (`endDate >= now`) subscriptions of the same user and vendor (`camap-hx/src/service/SubscriptionService.hx:118-127`); the POSTed id is validated only for "same user" (`camap-hx/src/service/SubscriptionService.hx:1104`), and `fromSubscription.getBalance()` runs (`:1100`) before the null check (`:1102`).

### Minimums / constraints
20. `distribMinOrdersTotal` (VAR): every not-yet-closed distribution (`orderEndDate >= now`) in submitted orders must total at least that amount; each line `roundTo(quantity * productPrice, 2)`; closed distributions skipped (`camap-hx/src/service/SubscriptionService.hx:581-602`). Error `CatalogRequirementsNotMet`.
21. `catalogMinOrdersTotal` (VAR, whole contract): required total = `floor(ratio * catalogMinOrdersTotal)` with `ratio = subscription distributions (absences excluded) / all catalog distributions`; without a subscription the numerator is "distributions with date >= next open distribution date" (`camap-hx/src/service/SubscriptionService.hx:485-515`, `:490-504`). The sum includes all orders of the subscription (`:604-622`); error message prints the unrounded total (`:618` vs `:613`). `areVarOrdersValid` throws "Aucune commande dans cette souscription" when constraints exist and there are zero orders (`camap-hx/src/service/SubscriptionService.hx:555-559`); invoked at create (`:697`), `updateOrders` (`:1018`), `updateDefaultOrders` for VAR (`:999-1001`). TS re-implements the pre-check client-side (`minSubscriptionOrder`, `camap-ts/packages/front-core/src/modules/csaCatalog/CsaCatalog.context.tsx:286-290`: `floor(catalogMin / distributions.length * remainingDistributions)`) and disables "save" if `distribMinOrdersTotal > total` or `minSubscriptionOrder > contractTotal` (`camap-ts/packages/front-core/src/modules/csaCatalog/containers/CsaCatalogOrdersMobile.tsx:297-341,352-373`).
22. Absent distributions are excluded from `getSubscriptionDistributions`, from the ratio of rule 21, and from the cron (rule 8); absence update re-creates/removes orders (`camap-hx/src/service/AbsencesService.hx:114-190`).

### Order creation / edit
23. `OrderService.make` (`camap-hx/src/service/OrderService.hx:30-139`): rejects null distribution/quantity, negative quantity, disabled vendor; non-integer quantity unless `canHaveFloatQt(product)` (= `variablePrice || bulk`, `:19-21,44-48`; integer test `camap-hx/src/tools/FloatTool.hx:9-16`); `multiWeight` with quantity > 1 splits into N rows of quantity 1 and requires an integer (`:52-65`); quantity 0 returns null (`:68`); `productPrice` snapshot = `product.price` (`:77`); `feesRate` only if `hasPercentageOnOrders()` which is hard-coded false (`:78-80`, `camap-hx/src/db/Catalog.hx:128-131`); same user+product+distribution rows merged (`:71,90-97`); basket = given or `Basket.getOrCreate` (`:100-103`); subscription mandatory (`:108-109`).
24. Stock (catalog `StockManagement` and `product.stock != null`): after insert, available stock `getAvailableStock(distribId, ignoreOrderId)`; stock 0 -> quantity set to 0 and error; insufficient -> clamped to available and an error is still thrown (`camap-hx/src/service/OrderService.hx:116-135`); multiWeight counts as 1 (`:121`). Stock = distribution (or global) stock minus sum of existing orders with `quantity>0` (`camap-hx/src/db/Product.hx:147-179`). `assertStocksAvailable` is the pre-check used by `checkDefaultOrder` (`camap-hx/src/service/OrderService.hx:141-160`).
25. `OrderService.edit` (`camap-hx/src/service/OrderService.hx:166-240`): negative refused; non-integer refused for non-float products; `paid` reset to false when quantity increases unless given (`:183-187`); `user2`/invert flags overwritten (`:190-197`); stock check (`:199-222`; clamp writes `availableStock * product.qt` at `:214-217` vs `make` writing `availableStock` at `:130`; over-stock test uses the old `order.quantity` for multiWeight `:207`); quantity 0 keeps the row with `quantity=0, paid=true` (`:225-228`; label "Canceled" `:366-367`). `editMultiWeight` (`:245-293`). `delete` only when quantity is 0 or `force` (`:298-325`) and refreshes the `SubscriptionTotal` operation; stock-decrement block commented out (`:309-316`).
26. `canModify` for the UI: VAR -> now strictly inside the distribution's order window (or `orderStartDate == null`), CONST -> `catalog.isUserOrderAvailable()`; never when `paid` (`camap-hx/src/db/UserOrder.hx:89-107`). `Distribution.canOrderNow()` (`camap-hx/src/db/Distribution.hx:154-165`).
27. Server-side window enforcement is partial: `OrderService.make/edit` and `SubscriptionService.setOrders` do not test the distribution order window; REST `updateOrders` only requires the catalog to have some open distribution for non-managers (`camap-hx/src/controller/api/Subscription.hx:70-73`, `camap-hx/src/service/SubscriptionService.hx:1021-1056`). The window is enforced by the TS UI (distribution `state` Open/NotYetOpen/Closed/Absent, `camap-ts/packages/front-core/src/modules/csaCatalog/interfaces.ts:77-100`) and by `Contract.doEditVarOrders` (`camap-hx/src/controller/Contract.hx:229`). Whether `MakeOrder` event listeners enforce it is unverified.
28. Order window definition: `Distribution.orderStartDate/orderEndDate` copied from the MD and overridden per catalog when `orderStartDaysBeforeDistrib` / `orderEndHoursBeforeDistrib` are non-null and non-zero (`camap-hx/src/service/DistributionService.hx:296-305`, `:299,303`); joining a distribution is refused for a CONST catalog with subscriptions, warning only for VAR (`:283-294`). See `distributions-volunteers.md`.
29. `setOrders` (`camap-hx/src/service/SubscriptionService.hx:1021-1057`): per (distribution, product) finds an existing order by `product + user + distributionId` (not by subscription) and edits it or creates it; errors rethrown as plain `Error`. `updateOrders` then refreshes `SubscriptionTotal` and runs `areVarOrdersValid` (`:1014-1019`).

### Admin order edit (OrderBox / back-office)
30. `createOrUpdateOrders` (`camap-hx/src/service/OrderService.hx:694-787`): `ordersData=[]` is an error; per line, finds an existing order by id among the user's orders of the catalog/multiDistrib and edits it with `paid`, or creates one for the subscription covering that distribution (`startDate <= distrib.date <= endDate`); line-level `tink.core.Error`s swallowed into session messages (`:734-737,759-762`); missing subscription throws (`:714,755`); updates `basket.total` and the `SubscriptionTotal` operation (`:775-784`); reads `multiDistrib.distribStartDate` (`:712`) so `multiDistrib` is effectively required (`multiDistrib == null` allowed at `:696-709`).

### Quantities, units, rounding
32. Order `quantity` is in product units; for smart-quantity products (`camap-ts/packages/camap-common/src/products/format.ts:57-63`; HX `camap-hx/src/service/OrderService.hx:19-21`) displayed amount = `quantity * product.qt` (`format.ts:76-91`, `camap-hx/src/service/OrderService.hx:365-372`, `camap-hx/js/react/order/redux/components/Order.hx:203-218`). TS front input: typed value / `product.qt` (`camap-ts/packages/front-core/src/modules/csaCatalog/components/CsaCatalogOrdersMobileProduct.tsx:86-101`).
33. Money rounding: HX sums per line `roundTo(quantity * productPrice, 2)` then rounds the total (`camap-hx/src/db/Subscription.hx:32-40`); `Basket.getOrdersTotal` rounds each line `quantity*productPrice*(1+feesRate/100)` after a `Std.string().parseFloat()` round-trip "neko float bug" (`camap-hx/src/db/Basket.hx:132-142`, `camap-hx/src/service/OrderService.hx:404-408`). TS `computeUserOrderAmount = roundPrice(roundPrice(qty*price) * (1+fees/100))` (`camap-ts/packages/camap-common/src/utils/index.ts:33-50,60`). `FloatTool.clean` rounds to 2 decimals (`camap-hx/src/tools/FloatTool.hx:19-23`). `ListSynchronizer` is a generic list sync helper (`camap-hx/src/tools/ListSynchronizer.hx:12-66`; used by `VolunteerService.updateVolunteers`).
34. Subscription balance (HX): `getPaymentsTotal() - getTotalPrice()` rounded, `paid() = balance >= 0` (`camap-hx/src/db/Subscription.hx:23-59`); the `SubscriptionTotal` operation holds `-getTotalPrice()` and is rewritten only when the amount changes (`camap-hx/src/service/SubscriptionService.hx:1059-1091`). `Subscription.defaultOrders` stores `productPrice` per `CSAOrder` (`camap-hx/src/service/SubscriptionService.hx:24`, `SubscriptionAdmin.hx:132-138`) but totals and `createRecurrentOrders` recompute from current price (`camap-hx/src/db/Subscription.hx:94-129`, `camap-hx/src/service/OrderService.hx:77`).
35. `paid` and `feesRate` are still live: `paid` written/read (`camap-hx/src/service/OrderService.hx:183-187,227`, `camap-hx/src/db/UserOrder.hx:105-106`, OrderBox toggle `camap-hx/js/react/order/redux/components/Order.hx:177-184`); `feesRate` read by `prepare` (`camap-hx/src/service/OrderService.hx:385-394`) and TS `computeUserOrderAmount`, always 0 for new orders.

## 5. Flows

### 5.1 Member creates a subscription (TS UI -> HX API)
1. Home/list links to `/subscriptions/contract/:id` (`camap-hx/lang/master/tpl/home.mtt:80,156`, `macros.mtt:269`) -> neo `csaCatalog` with current/coming subscription id.
2. TS loads `GET /api/catalog/:id`, stocks, then (if sub) `GET /api/subscription/:id` (`camap-ts/packages/front-core/src/modules/csaCatalog/CsaCatalog.context.tsx:112-141`).
3. Wizard `presentation -> absences (if absentDistribsMaxNb>0) -> requiredOrders (if CONST or any minimum) -> create` (`CsaCatalogRouter.tsx:91-136`). Optional `POST /api/subscription/checkDefaultOrder/:catalog` (`requests.tsx:156-162`).
4. `POST /api/subscription` `{userId, catalogId, defaultOrder, absentDistribIds, initialOrders}` -> permission checks (`camap-hx/src/controller/api/Subscription.hx:35-47`) -> `createSubscription` (rules 10-15) -> DTO.
5. Review step: CONST -> `POST updateDefaultOrder` (`CsaCatalogRouter.tsx:145-152`); VAR -> `POST updateOrders` with modified distributions (`:153-180`).

### 5.2 Admin orders for a member
- Batch order page: member `Select` + the same `CsaCatalogRouter` with `adminMode` (`camap-ts/packages/front-core/src/modules/batchOrder/BatchOrder.module.tsx:119-167`); member's subscription = first with `endDate >= now` (`:72-77`); with none, a "create subscription" button uses the same REST create (`CsaCatalogRouter.tsx:212-231`).
- Back-office "orders" page: OrderBox dialog (`/api/order/get|update`) or inline quantity inputs (`/api/order/updateOrderQuantity`).
- Admin form `/contractAdmin/subscriptions/insert|edit` is the only place to choose dates, `user2`/invert, and to edit a CONST subscription's recurrent order with admin privileges.

### 5.3 Deletion
Member: GET `/subscriptions/delete/:id` (owner, no token) -> `deleteSubscription`; admin: tokenised GET `/contractAdmin/subscriptions/delete/:id`. Both rely on rule 17.

### 5.4 Default order cron
Hourly: distributions whose `orderEndDate` fell in the last hour -> subscriptions covering the distribution date, not absent, with no order for that distribution -> `OrderService.make` for each default-order line -> notification mail `DEFAULT_ORDER(catalogId)` -> `createOrUpdateTotalOperation` (`camap-hx/src/controller/Cron.hx:227-278`).

### 5.5 Balance transfer (admin)
`/contractAdmin/subscriptions/payments/:sub` -> button -> `/contractAdmin/subscriptions/balanceTransfer/:sub` -> select target -> `SubscriptionService.transferBalance` (rule 19).

### 5.6 Legacy OrderBox (HX React)
`CatalogsBox` ("Choisissez le catalogue dont vous voulez voir les produits", back = `location.hash="/"`, 41 l.) mounts `CatalogSelector` (70 l.; on mount `OrderBoxThunk.fetchCatalogs(multiDistribId)` -> `GET /api/order/catalogs/<multiDistribId>?catalogType=1` `OrderBoxThunk.hx:120`; one catalog -> auto-select `:28-31`; select dispatches `SelectCatalog`, `location.hash="/insert"`); `ProductSelect` (67 l.; `GET /api/product/get/?catalogId=` `OrderBoxThunk.hx:150,156`; click -> `SelectProduct`, `location.hash="/"`). Redux actions enum `OrderBoxAction` (22 l.: FetchOrdersSuccess, FetchUsersSuccess, SelectUser, UpdateOrderQuantity, ReverseOrderRotation, UpdateOrderUserId2, UpdatePaid, FetchCatalogsSuccess, SelectCatalog, FetchProductsSuccess, SelectProduct, FetchFailure). `OrderBoxReducer` (156 l.): state `{orders, ordersWereFetched, users, selectedUserId/Name, catalogs, selectedCatalogId, products, error}` (`:12-21`); `SelectProduct` increments an existing line unless the product is `multiWeight`, else pushes a new `UserOrder` with negative random temporary id `0 - Std.random(1000000)` (`:116-148`, `:131`). Files under `camap-hx/js/react/order/redux/` and `camap-hx/js/react/product/redux/components/ProductSelect.hx`.
